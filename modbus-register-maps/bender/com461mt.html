Short answer

The COM461MT sits on a Bender internal BMS bus (RS-485) and republishes the data of up to 150 BMS devices (ISOMETER, RCMS, EDS, MK800, PRC changeover modules) as Modbus/TCP input registers. Each BMS address gets its own 256-register block: device name, timestamp, alarm flags, then 4 registers per channel (float value, alarm/unit byte pair, text code). This map shows the block for BMS address 1 (channels 1-12), the test record at address 0 and the command interface.

This page lists 50 Modbus registers for the Bender COM461MT BMS-to-Modbus/TCP gateway — 4 writable — with the table, 0-based wire address, data type, word order, scale, units and access of each, re-typed from Bender’s own free documentation (linked below) and checked against it.

Integration notes: Bender COM461MT BMS-to-Modbus/TCP gateway

Integration in brief

Read input registers (FC4) at BMS address x 0x100: register +0x0E tells you if the device has an alarm or has dropped off the bus, and each channel's float value sits at +0x10 + 4 x (channel-1). First read the test record at 0x0010/0x0014 (230.0 and 12.34) to prove your float word order.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

Set IP address, subnet mask, BMS address and 'Modbus control' (on/off) on the gateway's web page (factory IP 192.168.0.254, mask 255.255.0.0). Commands only work while Modbus control is enabled.

Byte order & addressing

  • Only FC4 (read input registers) is used for data; up to 125 registers per request. FC16 is used for the command block.
  • Some Modbus clients need an offset of 1 (start of the process image becomes 0x0101).
  • Commands: always write all four words 0xFC00-0xFC03 in one FC16 request, then poll 0xFC04 until it reads 2 (ready) or 1 (error).
  • BMS address 0 is a simulated device holding fixed test values; no real device can use address 0.

Network setup

  • Connect a PC to the COM461MT and browse to its IP to change network settings, BMS address, time zone and NTP server.
  • Terminate the internal BMS bus (RS-485, 9.6 kbit/s): switch on the COM461MT's terminating switch when it sits at the end of the bus.
  • Run a BMS bus scan so the gateway learns the device names shown at +0x00 of each block.

Watch out for

  • A block exists for every BMS address but only holds data for devices actually present; check the device-lost flag before trusting values.
  • The meaning of each channel depends on the connected Bender device type, not on the gateway.

Notes on this map

  • Only BMS device address 1 is listed. Every other device uses the same layout shifted by its address: BMS address N starts at N x 0x100 (e.g. address 3 channel 2 = 0x0314). Channel numbers in each block follow the BMS device's own channel list.
  • Channels 13-32 continue the 4-register pattern up to 0x008F within each block; channels 33-64 (MK800/TM800 master mode, digital only) are one byte each from 0x90 and are not listed.
  • Float word order: the manual states big-endian and gives the test value 12.34 at 0x0014 as words 0x4145, 0x70A4 (high word first), so ABCD is documented, not assumed.
  • Channel word 2 packs two bytes. High byte (AT&T): bits 0-2 alarm type (0 none, 1 prewarning, 2 device error, 4 alarm yellow LED, 5 alarm red LED), bit 6 internal test, bit 7 external test. Low byte (R&U): bits 0-4 unit (1 none, 2 ohm, 3 A, 4 V, 5 %, 6 Hz, 7 baud, 8 F, 9 H, 10 degC, 11 degF, 12 s, 13 min, 14 h, 15 day, 16 month, 30 CODE), bits 6-7 validity (0 true value, 1 true value smaller, 2 larger, 3 invalid).
  • When the unit is CODE the float holds an internal code, not a measurement; read the description code (word 3) and Bender's text table in ch. 7.4.
  • Unit ID is not specified in the manual; its example request uses unit identifier 0x01. The TCP port is not stated.
  • The device's own BMS address on the internal bus is 2 by factory default (range 1-99).

Questions about the Bender COM461MT BMS-to-Modbus/TCP gateway

What Modbus registers does the Bender COM461MT BMS-to-Modbus/TCP gateway have?

This map lists 50 registers: 46 input registers, 4 holding registers. 4 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Bender COM461MT BMS-to-Modbus/TCP gateway Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers hexadecimal, 0-based. Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. Addresses are printed in hex and go on the wire as-is: the manual's example request for BMS device 1 puts 0x0100 in the start-address field. Block start = BMS address x 0x100; channel n of that device starts at block + 0x10 + 4 x (n-1). Bender notes that some clients need 1 added (process image then starts at 0x0101).

What byte order does the Bender COM461MT BMS-to-Modbus/TCP gateway use for 32-bit values?

Multi-register values in this map use ABCD (high word first (big-endian)). Set your client to this order for every 32/64-bit value in the table.

What are the minimum Modbus registers to integrate the Bender COM461MT BMS-to-Modbus/TCP gateway?

Start with IR 20 Reference: channel 2 value (Test value 12.34 - check word order once); IR 270 Device 1: common alarm / device lost (Common alarm and device-lost flags); IR 272 Device 1: channel 1 value (Channel 1 measured value); IR 274 Device 1: channel 1 AT&T / R&U (Channel 1 alarm type and unit); IR 275 Device 1: channel 1 description code (Channel 1 text code); IR 64516 Command status (Status of the last command).

How do I enable Modbus control of the Bender COM461MT BMS-to-Modbus/TCP gateway?

Set IP address, subnet mask, BMS address and 'Modbus control' (on/off) on the gateway's web page (factory IP 192.168.0.254, mask 255.255.0.0). Commands only work while Modbus control is enabled.

Where is the official Bender COM461MT BMS-to-Modbus/TCP gateway Modbus documentation?

The source is COM461MT Operating Manual - BMS Ethernet gateway for the connection of Bender devices with BMS support to Ethernet (TCP/IP) using the Modbus/TCP protocol (COM461MT_D00011_01_M_XXEN/08.2020), revision 2020-08, published free by Bender at https://www.bender.de/fileadmin/content/Products/m/e/COM461MT_D00011_M_XXEN.pdf.
