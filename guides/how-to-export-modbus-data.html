How do I collect and export Modbus data with Easy Modbus?

Updated 30 September 2026

Short answer

Save the readings you care about on each device, then on the main screen tap Export Report. The app reads every saved reading on every device, builds one CSV with names, addresses in three conventions, data type, word order, scaling, units, the live value and any error, and hands it to your email or file app. To send just one device's register map, open the device and choose ⋮ → Export this map. The free version asks whether you want to watch a short ad before an Export Report; the one-time unlock removes it.

Step 1 — Collect: save the readings

An export contains the readings you have saved — Modbus will not tell anyone what its registers are, so the map you build is the content. For each device:

  1. Open the device and tap Add a Reading. In Easy mode choose what kind of value it is; in Pro mode fill in the full editor. Give it a name (“AHU-1 supply air temp”), the address as your manual writes it, and check the test read looks right.
  2. Have a vendor spreadsheet? ⋮ → Import map from CSV and paste it instead of typing forty rows.
  3. Tap Read All to read every saved reading in as few requests as the device allows. Rows that fail show why when you tap them.

Step 2 — Export the report

  1. Back on the main screen, tap Export Report.
  2. Free version: you are asked Watch a short ad? — choose Watch ad, Remove ads (the one-time unlock) or Cancel. With no signal, no ad loads and the export simply goes ahead.
  3. The app reads every device again, so the values are current, then opens the share sheet with EasyModbus_YYYYMMDD_HHMM.csv attached. Pick email, Drive, Teams or anything else; nothing is uploaded anywhere by the app.

What is in the CSV

ColumnMeaning
Device Name, Host, Port, Unit ID, TransportWhich device the row came from (Transport is TCP or RTU_OVER_TCP).
Reading NameThe name you gave the reading.
TableCoil, discrete input, input register or holding register.
Wire Address, Register Number, ModiconThe same address three ways: 0-based on the wire, 1-based, and 40001-style. See why addresses are off by one.
Data Type, Word Order, BitHow the raw registers are decoded.
Multiplier, Offset Value, UnitsScaling applied to get the value shown.
ValueThe live value at export time.
StatusBlank when the read worked; otherwise the reason it failed.
NotesYour notes from the manual.

A device with no readings yet still gets a row, so nothing on site vanishes from the report.

Other ways to get data out

  • One device’s map: device ⋮ → Export this map — the same columns, one device, no ad. It is also the way to move a map to another phone (import it there with Import map from CSV), because the app's data is deliberately not included in phone backups.
  • A control panel: long-press it on the Control Panels screen to save a .empanel file. See building a control panel.
  • A trend: export at intervals; each file name carries the date and time, so a series lines up in Excel. See log Modbus data to CSV.
  • What you changed: main screen ⋮ → Session write log lists every write this session with the before and after values.

A register map names a customer's equipment and the addresses that control it. Send it to the people who need it, not to everyone.
