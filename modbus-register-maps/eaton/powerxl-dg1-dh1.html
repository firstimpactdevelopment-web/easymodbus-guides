Short answer

The PowerXL DG1 and DH1 are Eaton variable frequency drives with on-board RS-485 (Modbus RTU, BACnet MS/TP) and Ethernet (Modbus TCP, EtherNet/IP, BACnet IP). Both expose the same Modbus layout: monitoring values by ID, a fixed process-data block for control and status, and parameters by ID. This map covers the control and status words, speed reference, default process data and the main monitoring IDs.

This page lists 25 Modbus registers for the Eaton PowerXL DG1 / DH1 drives (on-board Modbus RTU / TCP) — 6 writable — with the table, 0-based wire address, data type, word order, scale, units and access of each, re-typed from Eaton’s own free documentation (linked below) and checked against it.

Integration notes: Eaton PowerXL DG1 / DH1 drives (on-board Modbus RTU / TCP)

Integration in brief

Write the control word at 2000 (bit 0 run, bit 1 reverse, bit 2 reset, bits 8-9 for fieldbus control and reference) and the speed reference at 2002, then read status 2100 and process data out 2103-2109.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

Select Modbus RTU in RS485 comm set (DG1 P20.3.1.1 / DH1 P12.3.1.1, ID 586) and set slave address, baud rate and parity in the same group; set the control place and reference source to fieldbus.

Communication loss & watchdog

DG1 has a Modbus RTU communication time-out (P20.3.2.9, ID 593, printed default 10000 ms); P20.3.2.10 / P12.3.2.6 (ID 2516) chooses whether a comm loss faults only in fieldbus control or in all control places.

Byte order & addressing

  • Process data and IDs are Modicon-style: subtract 1 (and 40001) for the wire address.
  • Holding and input registers are the same data (function 03 or 04).

Network setup

  • Slave address range 1-247, default 1.
  • Parity choice also sets stop bits: none = 2 stop bits, odd/even = 1 stop bit.
  • Defaults: 19200 baud, even parity, 1 stop bit.

Watch out for

  • Control word bits 8 (FB control) and 9 (FB reference) must be set for the drive to take run and speed from the bus.

Notes on this map

  • This copy is hosted by the US distributor Precision Electric; it is Eaton manual MN040010EN (June 2018).
  • Scales come from the 'Display format' column of the parameter ID lists (x100 = two decimals, x10 = one decimal, x0 = none) and from the Appendix B process-data table. INTEGER items are typed INT16 here (the process-data range is printed -32768...32767).
  • Process data out 8 is left out: the RTU chapter says it defaults to ID 28 (latest fault code) while Appendix B says FB Data Out 8 Sel defaults to ID 8 (unit temperature). Read ID 28 directly instead. Process data in 2-3 (setpoint/feedback) have no fixed unit and are left out.
  • Left out: every 4-byte (DOUBLE) value such as energy counters, PID setpoints/feedback and instant motor power, because the manual only says data is big endian and does not state the word order of 32-bit values; the FB general status word 2102, whose 'not used' bit marks did not survive in the table.
  • The DH1 menu codes are P12.3.x for RS-485 settings, the DG1 codes P20.3.x.
  • Left out: monitoring IDs whose unit the manual does not settle: analog inputs 1-2 and analog output 1 (IDs 10, 11, 25; the BACnet object table calls them volts), PT100 temperature (ID 27) and the PID1/PID2 outputs (IDs 22, 38).
  • RTU defaults from Table 8: slave address 1, baud rate code 1 (19200), parity code 2 (even, 1 stop bit). Data bits are not stated.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. Questions about the Eaton PowerXL DG1 / DH1 drives (on-board Modbus RTU / TCP)

What Modbus registers does the Eaton PowerXL DG1 / DH1 drives (on-board Modbus RTU / TCP) have?

This map lists 25 registers: 25 holding registers. 6 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Eaton PowerXL DG1 / DH1 drives (on-board Modbus RTU / TCP) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers Modicon 3xxxx/4xxxx (drop the prefix, subtract 1). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. The manual pairs each drive ID with a 4x register (ID 2001 = 42001, ID 1 = 40001) and its frame examples read 'holding registers 2000-2003' with start address 07D0h, so ID n goes on the wire as n-1 (40001 = address 0).

What are the minimum Modbus registers to integrate the Eaton PowerXL DG1 / DH1 drives (on-board Modbus RTU / TCP)?

Start with HR 2000 FB control word (Control word); HR 2002 FB speed reference (Speed reference 0.01 %); HR 2100 FB status word (Status word); HR 2103 Process data out 1 (output frequency) (Output frequency); HR 2105 Process data out 3 (motor current) (Motor current); HR 27 Latest fault code (Latest fault code).

How do I enable Modbus control of the Eaton PowerXL DG1 / DH1 drives (on-board Modbus RTU / TCP)?

Select Modbus RTU in RS485 comm set (DG1 P20.3.1.1 / DH1 P12.3.1.1, ID 586) and set slave address, baud rate and parity in the same group; set the control place and reference source to fieldbus.

What happens when the Eaton PowerXL DG1 / DH1 drives (on-board Modbus RTU / TCP) loses Modbus communication?

DG1 has a Modbus RTU communication time-out (P20.3.2.9, ID 593, printed default 10000 ms); P20.3.2.10 / P12.3.2.6 (ID 2516) chooses whether a comm loss faults only in fieldbus control or in all control places.
