Short answer

The FUTURA is a residential heat recovery ventilation unit with a built-in Modbus TCP server. Input registers give air temperatures, humidity, fan data, power and connected room-sensor values; holding registers set the ventilation mode, timed functions, setpoints and external sensor values. This page lists the 16-bit registers of the Futura L/M/S layout.

Integration notes: Jablotron FUTURA L / M / S heat recovery ventilation unit (Modbus TCP)

Integration in brief

Connect over Modbus TCP to port 502, unit ID 1. Read input registers 30-48 with function 04 for temperatures, humidity and fans, and write holding register 0 for the ventilation mode or 1-5 to start timed boost, circulation, overpressure, night or party functions.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

The Modbus TCP server is built in; no enable step is documented.

Byte order & addressing

  • Only one TCP socket is available. A second client (another BMS or app gateway) blocks the connection.
  • Multi-register values must be read or written in one request (function 03/04, or 16 to write); a partial read returns ILLEGAL DATA ADDRESS.

Network setup

  • Unit ID 1, TCP port 502.

Watch out for

  • The Futura L+ uses a different, shorter address layout; do not use these addresses on an L+.

Notes on this map

  • Jablotron does not appear to host this list publicly; the link is the unaltered maker document as mirrored by the integrator TapHome.
  • Left out: every 32-bit register (serial number, firmware revision, operation-mode, error and warning words at 16-21, away start/end timestamps, Modbus counters, connected-device masks). The list does not say which register holds the high word.
  • Left out: preferred humidity (holding 11), whose unit is printed as 0.1 % while its values are listed as 25/50/75; the backup battery voltage (unit printed as 0.001 mV); the per-device options bit registers; sensor corrections; external sensor invalidate and floor temperature; external buttons; and the service/password registers 900-922.
  • Wall UI blocks repeat every 5 registers from 100 (3 units), wall sensors every 5 from 115 (8 units), ALFA units every 10 from 160 (8 units). External sensor values written by the master repeat every 10 from 300 (8 sensors). The zone CO2/temperature block at 100-173 exists only on the L+ and is not listed.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. Questions about the Jablotron FUTURA L / M / S heat recovery ventilation unit (Modbus TCP)

What Modbus registers does the Jablotron FUTURA L / M / S heat recovery ventilation unit (Modbus TCP) have?

This map lists 162 registers: 112 input registers, 50 holding registers. 50 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Jablotron FUTURA L / M / S heat recovery ventilation unit (Modbus TCP) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 0-based (the number printed is the address on the wire). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. Addresses are printed as protocol addresses and start at 0 (input register 0 is the product ID), so they are sent unchanged.
