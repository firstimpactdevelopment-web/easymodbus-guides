Short answer

The DCM1 is a two-part DC meter (DCM-D display/meter plus DCM-T transducer) for DC fast chargers, with RS485 Modbus RTU and Modbus TCP. Readings are 32-bit integers sent low word first with fixed weights. This map covers voltage, current, power, energy and Ah counters, run hours, shunt temperatures, serial and Ethernet settings, resets, the device state word and the main OCMF charging-session registers.

Integration notes: Carlo Gavazzi DCM1 DC energy meter for EV chargers (Modbus RTU / TCP)

Integration in brief

Poll input registers 0000h-0005h (function 04 or 03) for V, A and W and 0010h-0027h for energy; values are INT32 low word first with fixed weights. For signed charging sessions follow the OCMF procedure around 7040h and 7100h.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

RS485 and Ethernet are both active. Serial settings at 2000h-2004h take effect after writing 1 to 2010h; Ethernet settings at 2100h-210Dh after writing 1 to 210Eh or a power cycle.

Byte order & addressing

  • 32-bit and 64-bit unsigned values are low word first.
  • Totals are 0.1 kWh resolution; run hours are in 1/100 h.
  • Certified versions block the total-energy reset.

Network setup

  • Serial defaults: address 1, 9600 baud, no parity, 1 stop bit.
  • Ethernet defaults: 192.168.1.10 / 255.255.255.0, gateway 192.168.1.1, port 502, DHCP off.
  • With DHCP on, read the assigned address at 2120h-2123h.

Watch out for

  • Max RS485 answer time is 500 ms; use a long enough timeout.
  • After reading an OCMF file, write 0 to 7100h or no new session can start.

Notes on this map

  • Word order: the protocol says INT32, UINT32 and UINT64 are sent least significant word first with bytes MSB first, so those values are CDAB here.
  • Left out: the FLOAT block at 0200h (no word order stated for IEEE 754), INT64 energy blocks at 0500h/0600h and the INT64 UTC timestamp at 7032h (word order stated only for unsigned 64-bit), the mirror block at 0100h, the signed OBIS maps at 0700h/0800h, public keys, signatures, display page filters, MAC address, OCMF identification fields, custom display strings, the OCMF file buffer, maintenance mode and the cable-loss datalogger.
  • When the DCM-T transducer is unplugged, its values read 0x7FFF or 0x7FFFFFFF and the device state flags it.
  • The part-number table gives code 1832 for both ULB variants, with hex 0x0728 and 0x0729; check the code on the unit.
  • The charging-session procedure (sync clock at 7031h/7032h, write 'B' to 7040h, read 7A00h-7A08h, write 'E', read and acknowledge the OCMF file at 7100h-7110h) is described in the source.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. Questions about the Carlo Gavazzi DCM1 DC energy meter for EV chargers (Modbus RTU / TCP)

What Modbus registers does the Carlo Gavazzi DCM1 DC energy meter for EV chargers (Modbus RTU / TCP) have?

This map lists 71 registers: 23 input registers, 48 holding registers. 32 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Carlo Gavazzi DCM1 DC energy meter for EV chargers (Modbus RTU / TCP) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers Modicon 3xxxx/4xxxx (drop the prefix, subtract 1). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. Rows give a 6-digit Modicon number (3xxxxx for function 04, 4xxxxx for function 03) and the hex physical address that goes in the frame. 300001 / 0000h is wire address 0. Functions 03 and 04 return the same data.

What byte order does the Carlo Gavazzi DCM1 DC energy meter for EV chargers (Modbus RTU / TCP) use for 32-bit values?

Multi-register values in this map use CDAB (low word first (word-swapped)). Set your client to this order for every 32/64-bit value in the table.

What are the minimum Modbus registers to integrate the Carlo Gavazzi DCM1 DC energy meter for EV chargers (Modbus RTU / TCP)?

Start with IR 0 Voltage (DC voltage); IR 2 Current (DC current); IR 4 Power (DC power); IR 16 kWh (+) TOT (Imported energy total); IR 32 kWh (-) TOT (Exported energy total); HR 20498 Device state (Device state / transducer health); HR 28741 Charging status (Charging session status).

How do I enable Modbus control of the Carlo Gavazzi DCM1 DC energy meter for EV chargers (Modbus RTU / TCP)?

RS485 and Ethernet are both active. Serial settings at 2000h-2004h take effect after writing 1 to 2010h; Ethernet settings at 2100h-210Dh after writing 1 to 210Eh or a power cycle.
