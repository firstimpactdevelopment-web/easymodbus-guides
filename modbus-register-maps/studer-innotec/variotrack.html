Integration notes: Studer Innotec VarioTrack MPPT solar charge controller (via Xcom-485i)

Integration in brief

Fit an Xcom-485i on the Studer communication bus and poll it as a Modbus RTU slave. Each Studer device answers at its own unit ID (offset set by DIP switches 1-2); read infos with function 04 and parameters with 03, always 2 registers at a time, and decode as big-endian float.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

Install the Xcom-485i on the Studer bus. DIP switches 1-2 set the unit-ID offset (0, 32, 64 or 128) and switches 7-8 set the baud rate (9600, 19200, 38400 or 115200). Frames are 8 data bits, even parity, 1 stop bit.

Byte order & addressing

  • Unit 21 addresses the first VarioTrack; multicast unit 20 reads the first such device and writes to all of them at once.
  • Values are floats even for on/off and enumerated items: 1.0 = 0x3F800000.

Network setup

  • With DIP 1-2 off: unit 1 = Xcom-485i gateway, 2 = system, 10 = all Xtenders, 11-19 = single Xtenders, 20 = all VarioTracks, 21-35 = single VarioTracks, 40 = all VarioStrings, 41-55 = single VarioStrings, 60 = all BSP/Xcom-CAN BMS, 61 = the single BSP or Xcom-CAN BMS. Add the DIP offset to each.
  • Single devices are numbered in the order shown on the RCC remote's device list.
  • Allow up to 1 s for a reply and send one request at a time; the gateway is slower when the Studer bus is busy.

Watch out for

  • Writing a parameter at its base register stores it in flash; cyclic writes should use base + 6000 (RAM only).
  • Some parameters restart an internal timer or algorithm when changed while running.
  • Parameter levels (Basic/Expert/Installer/QSP) are the RCC access levels printed in the appendix.

Notes on this map

  • Every info and parameter is an IEEE 754 single-precision float in two registers, high word first. The protocol spec's example reads Xtender info 3001 as 0x41D3 0x3333 = 26.4 °C, and parameter 1107 as 0x4170 0x0000 = 15.0 A.
  • Each request must read or write exactly 2 registers (one value); asking for more returns an exception. Infos use function 04, parameters function 03 to read and 16 to write.
  • Parameter registers have three more views at fixed offsets: +2000 = minimum allowed value, +4000 = maximum allowed value (read only), +6000 = write to RAM only. Use the RAM-only offset for anything written repeatedly; flash is only guaranteed for about 1000 writes per parameter.
  • Enumerated infos count 0, 1, 2 ...; enumerated parameters use one bit per option (1, 2, 4, 8), still sent as a float. Codes shown as '---' in the appendix are unused and left out of the value lists.
  • Register names keep the Studer info/parameter number in braces, e.g. {3000}. The register is 2 x (number - base) for that device family.
  • Parameters whose appendix format is MENU are menu headings, not values, and are left out. The appendix's per-row remarks column is not reproduced.
  • The gateway's own input registers (pending messages at 0-4, device counts at 5-9, gateway identity at 10-14, on unit 1) and the system clock (holding registers 0-7 on unit 2) are described in the protocol spec but live at other unit IDs, so they are not in this register list.
  • The protocol spec's first read example prints the value as 0x4170 in the PDU table but 0x41F0 in the serial-line frame; 0x4170 matches the stated 15.0 A.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. Questions about the Studer Innotec VarioTrack MPPT solar charge controller (via Xcom-485i)

What Modbus registers does the Studer Innotec VarioTrack MPPT solar charge controller (via Xcom-485i) have?

This map lists 318 registers: 55 input registers, 263 holding registers. 263 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Studer Innotec VarioTrack MPPT solar charge controller (via Xcom-485i) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 0-based (the number printed is the address on the wire). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. The appendix lists the register exactly as it goes in the request. The protocol spec's example reads info 3001 from register 2 with start address 0x0002 in the frame, and parameter 1107 from register 14 (0x000E).

What byte order does the Studer Innotec VarioTrack MPPT solar charge controller (via Xcom-485i) use for 32-bit values?

Multi-register values in this map use ABCD (high word first (big-endian)). Set your client to this order for every 32/64-bit value in the table.

What are the minimum Modbus registers to integrate the Studer Innotec VarioTrack MPPT solar charge controller (via Xcom-485i)?

Start with IR 0 Battery voltage {11000} (Battery voltage); IR 2 Battery current {11001} (Battery current); IR 4 Voltage of the PV generator {11002} (PV voltage); IR 8 Power of the PV generator {11004} (PV power); IR 14 Production in (kWh) for the current day {11007} (Energy produced today); IR 18 Total produced energy {11009} (Total produced energy); IR 32 Operating mode {11016} (Operating mode); IR 68 Type of error {11034} (Type of error).

How do I enable Modbus control of the Studer Innotec VarioTrack MPPT solar charge controller (via Xcom-485i)?

Install the Xcom-485i on the Studer bus. DIP switches 1-2 set the unit-ID offset (0, 32, 64 or 128) and switches 7-8 set the baud rate (9600, 19200, 38400 or 115200). Frames are 8 data bits, even parity, 1 stop bit.
