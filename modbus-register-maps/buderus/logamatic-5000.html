Short answer

The Logamatic 5000 series is Buderus' commercial boiler and heating-system controller, with a Modbus TCP server on its LAN 1 port. A BMS can send a flow-temperature or output demand to the boiler strategy, set heating-circuit and hot-water setpoints, and read outdoor, system, circuit and per-boiler temperatures, output, pressure and HMI status. This map covers the master controller's system, strategy, cascade, DHW 1, heating circuits 00-01 and boiler 1 points.

Integration notes: Buderus Logamatic 5000 boiler and system controller (Modbus TCP, datapoint list 4.0)

Integration in brief

On the controller set LAN 1 to Modbus TCP/IP, turn on Modbus communication, write access and extended monitor data, then poll the controller at port 502, unit ID 255. To make it fire, write 1 to holding 402, the flow setpoint (°C) to 400 and 7 to the strategy bit block 405; read outdoor 0, system flow 4, boiler 1 flow 8001 and status 8012/8013.

Enable Modbus control & writes

Service menu > Connectivity: Local Area Network = Modbus TCP/IP (factory: Internet); Modbus communication = with or without heartbeat ('No' disables Modbus); Allow write access = On; Provide extended monitor data = On (factory Off, required for Modbus data). Then Service menu > Heat generation > Strategy data > Basic settings: enable 'Heat demand via Modbus' (and disable 'Internal heat demand' for exclusive BMS control).

Communication loss & watchdog

With 'Modbus communication = with heartbeat', the BMS must keep writing a changing counter to holding 0; holding 1 echoes it. If no new value arrives within the timeout (120-600 s, default 180 s) the controller raises a 'connection to building management faulty' message. 'Without heartbeat' disables loss detection.

Byte order & addressing

  • Addresses in the list are already 0-based wire addresses; add 30001/40001 only if your BMS uses Modicon notation.
  • 32-bit values (starts, operating time, fault keys) are high word first; some BMSs read the unsigned fault keys as negative signed values.
  • The display code at 8019 is two ASCII characters packed into one register.
  • Temperature demand (400) is whole degrees while most temperatures read back are x10.

Network setup

  • Connect LAN 1 on the BCT 531 module to the BMS network; do not use the 172.31.42.x range, which the controller uses internally.
  • Set a static IP (or DHCP) in the Connectivity menu and save.
  • The unit ID is 255 by default; the guide says it can be changed from firmware 1.5.13 (the download page says 1.6).
  • Firmware below 1.3 uses an older address list; a compatibility mode for firmware below 1.3.6 exists but should only be enabled for existing old integrations.

Watch out for

  • The strategy bit block must include the lead-boiler bit (bit 0) from firmware 1.3.3, and with an FM-CM cascade module the lead-boiler function must be enabled.
  • Output-led demand (401) works only in exclusive mode (internal heat demand off) and only when all boilers on the controller are the same type.
  • Points for hardware that is not fitted still answer, with invalid values such as 0 °C; writes to them are accepted but have no effect.
  • A boiler in lockout or manual mode ignores heat demand until it is ready again.

Notes on this map

  • Download page: https://www.buderus.de/de/unternehmen/5000-modbus-9710 (public). The ZIP holds the Excel datapoint list, the German user guide and a message-key list. The page also states Modbus TCP port 502 and default unit ID 255.
  • Scaling: registers marked 'x10' in the list are divided by 10 (scale 0.1). Setpoints without that mark (e.g. system flow setpoint 400) are whole units.
  • Types follow the list: 'int' (0-65535) is UINT16, 'signed int' INT16, 'long' INT32, 'unsigned long' UINT32. The user guide says 32-bit values are big-endian with the high register at the lower address (worked example on fault register 476/477), so ABCD.
  • Addresses here are for a controller that is the master (rotary switch 0). For a slave controller read through the master, add switch position x 500 to addresses below 8000 (the list has ready-made Slave01-Slave15 sheets).
  • Heating circuits 02-08 follow the same layout as circuit 01 at a 13-register stride (input flow temperature 115, 128, ... 193; holding blocks 83, 96, ... 161). Boilers 2-16 repeat the boiler 1 block at +40 (8040, 8080, ...). Only circuit 00, circuit 01 and boiler 1 are listed here.
  • Left out: DHW 2, alternative heat generator, heat pump, CHP, solar, fresh-water station, FM-SI, cascade buffer-charging settings, fault extra-info registers 484-499 and the 'reserved for legacy purposes' block. The cascade counters 360-362 are left out because the list gives no meaning for their values (count or bit mask).
  • Fault registers hold message keys that are decoded with the Buderus message-key list (also in the ZIP); a value stays until the message clears.
  • Coils and discrete inputs are not used by the controller (function codes 01, 02, 05 and 15 are listed as supported, but the guide says they are not used).
  • Not listed: fault registers 5-10 at input 266-277 (unsigned long pairs, same format as 476-483), added to the list for firmware after 1.8; up to 1.8 only registers 1-4 exist and the newest message is always in register 1.

Questions about the Buderus Logamatic 5000 boiler and system controller (Modbus TCP, datapoint list 4.0)

What Modbus registers does the Buderus Logamatic 5000 boiler and system controller (Modbus TCP, datapoint list 4.0) have?

This map lists 109 registers: 82 input registers, 27 holding registers. 26 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Buderus Logamatic 5000 boiler and system controller (Modbus TCP, datapoint list 4.0) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 0-based (the number printed is the address on the wire). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. The datapoint list gives decimal addresses that go straight into the request. Buderus' own conversion is Modicon = 40000 (holding) or 30000 (input) + address + 1, so holding register 400 is 40401 in Modicon notation.

What byte order does the Buderus Logamatic 5000 boiler and system controller (Modbus TCP, datapoint list 4.0) use for 32-bit values?

Multi-register values in this map use ABCD (high word first (big-endian)). Set your client to this order for every 32/64-bit value in the table.

How do I enable Modbus control of the Buderus Logamatic 5000 boiler and system controller (Modbus TCP, datapoint list 4.0)?

What happens when the Buderus Logamatic 5000 boiler and system controller (Modbus TCP, datapoint list 4.0) loses Modbus communication?

With 'Modbus communication = with heartbeat', the BMS must keep writing a changing counter to holding 0; holding 1 echoes it. If no new value arrives within the timeout (120-600 s, default 180 s) the controller raises a 'connection to building management faulty' message. 'Without heartbeat' disables loss detection.
