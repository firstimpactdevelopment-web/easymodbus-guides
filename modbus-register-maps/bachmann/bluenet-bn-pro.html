Short answer

BlueNet BN PRO is a family of intelligent rack PDUs with metering at inlet, phase and outlet level, residual-current monitoring and optional sensors. Modbus TCP exposes everything as read-only holding registers (FC 03) with fixed decimal resolutions. This map covers inlet, phase and outlet measurements, energy counters, MCB and RCM status, residual currents, GPIO and external temperature/humidity sensors.

This page lists 518 Modbus registers for the Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP) — 0 writable — with the table, 0-based wire address, data type, word order, scale, units and access of each, re-typed from Bachmann’s own free documentation (linked below) and checked against it.

Integration notes: Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP)

Integration in brief

Connect to the PDU's IP address with Modbus TCP, unit ID 1 for a single or main PDU, and read holding registers with FC 03. Inlet values start at address 16; scale each register by its resolution.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

The register list does not say how Modbus TCP is enabled on the PDU or which TCP port it uses; check the BlueNet PDU documentation.

Byte order & addressing

  • Register numbers are 1-based; send the decimal address (register - 1).
  • Values are integers with fixed resolutions (0.01 A, 0.1 V, 1 W, 0.1 kWh, 0.1 °C).
  • Linked PDUs use unit IDs by cluster position.

Network setup

  • Use unit ID 1 for single and main PDUs.
  • Read-only access with function code 03.

Watch out for

  • Status registers return negative codes (e.g. -2 connection lost) for offline outlets or sensors.
  • Read each energy pair (high + low register) in one request to avoid a torn value.

Notes on this map

  • Energy counters are split into a register named 'High Byte' followed by one named 'Low Byte'. Each pair is listed as one 32-bit value at the 'High' register, high word first (ABCD), as the names indicate.
  • The list gives a resolution for each value but no data type. Status and power-factor-suffix codes include negative numbers, so they are INT16; temperatures are listed as INT16, other measurements as UINT16. Check signedness on site if a value can go negative.
  • Single and main PDUs answer to unit ID 1. Linked PDUs in a cluster answer to the unit ID of their position in the cluster.
  • Power factor is unsigned (resolution 0.001); the separate 'Power Factor Suffix' register says whether the load is inductive (1, LA) or capacitive (-1, LE).
  • MCB current registers are left out: the list prints no resolution or unit for them.
  • Several hex addresses in the list do not match the decimal column (e.g. phase 2 suffix: register 182 printed as 0x00B1 but decimal 181); the decimal column, which always equals register - 1, is used.
  • The list is read-only (FC 03 only); there are no switching or reset registers.
  • Outlet blocks are listed for outlets 1-36.
  • Humidity rows print only '%' as resolution; they are listed with scale 1.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. New to this? Read what a register map is and why addresses are off by one.

Questions about the Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP)

What Modbus registers does the Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP) have?

This map lists 518 registers: 518 holding registers. 0 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 1-based (subtract 1 for the wire address). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. Each row prints a 1-based register number plus the 0-based wire address in hex and decimal. The 'documented' column here is the register number; the address is the printed decimal address (register - 1). Register 18 (inlet current) is requested as address 17 (0x0011).

What byte order does the Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP) use for 32-bit values?

Multi-register values in this map use ABCD (high word first (big-endian)). Set your client to this order for every 32/64-bit value in the table.

What are the minimum Modbus registers to integrate the Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP)?

Start with HR 16 Status Inlet State (Inlet status); HR 17 Inlet level - Current (Inlet current); HR 19 Inlet level - Active Power (Inlet active power); HR 22 Inlet level - Active Energy (Inlet active energy); HR 143 Phase 1 level - Voltage (Phase 1 voltage); HR 28 Inlet level - Frequency (Frequency); HR 443 RCM 1 - RCM AC (RCM 1 AC residual current).

How do I enable Modbus control of the Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP)?

The register list does not say how Modbus TCP is enabled on the PDU or which TCP port it uses; check the BlueNet PDU documentation.

Where is the official Bachmann BlueNet BN PRO intelligent PDU (Modbus TCP) Modbus documentation?

The source is BlueNet BN PRO Modbus TCP v1.00 Protocol - ModBus Register (Read Holding Register 0x03) (BN_PRO_Modbus-Register v1.00 REV00), published free by Bachmann at https://www.bachmann.com/fileadmin/05a_Downloads/BlueNet/BN_PRO/BN_PRO_Modbus-Register_v1.00_REV00.pdf.
