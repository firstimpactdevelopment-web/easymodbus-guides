Short answer

Walchem W-series and Intuition controllers run cooling tower, boiler and process water treatment. With the Modbus/TCP feature enabled they act as a Modbus TCP server on port 502. Data is laid out in 36-address blocks per object (system, network, each sensor input, digital input, relay); this map covers the system and network blocks and the key values of each I/O block, with 32-bit floats and integers sent low word first.

Integration notes: Walchem W900 water treatment controller (Modbus/TCP)

Integration in brief

Enable Modbus/TCP in the controller's Remote Communications menu, connect to port 502 with any unit ID except 0, and read values as CDAB 32-bit pairs. Poll no faster than every 5 s.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

Modbus/TCP is a feature of the controller; enable it and set the port and data format (normal or inverse word order) in the Remote Communications menu. A 'Verbose Logging' option there logs every message for commissioning and turns itself off at restart.

Byte order & addressing

  • Addresses are 1-based: subtract 1 for the wire address.
  • Floats and 32-bit integers are low word first (CDAB) unless 'inverse' format is selected.
  • Unit ID 0 is treated as broadcast: the request is processed but no reply is sent.
  • FC1/FC2 and FC3/FC4 are interchangeable on reads.

Network setup

  • Network address, port (default 502) and data format are set on the controller's communications menus.
  • Read up to 125 registers per request.

Watch out for

  • Polling faster than once every 5 seconds is unsupported.
  • Block start addresses depend on the controller model and on which I/O cards are fitted; confirm the I/O channel map for your unit.
  • Modbus RTU is not supported; serial masters need a TCP gateway.

Notes on this map

  • 32-bit integers and floats are sent least significant word first (CDAB) by default. The Remote Communications menu has an 'inverse' data format that swaps to high word first (ABCD); if values look wrong, check that setting.
  • All 32-bit integers are unsigned; times are Unix seconds since 1970-01-01.
  • Every address can be read as a holding register (FC3) or input register (FC4); this map lists them as holding registers. Booleans (the bold rows in the manual) can also be read as coils/discrete inputs at the same number.
  • Sensor blocks use the general sensor map (all sensor types except Digital Sensor and Analog Input Flowmeter, which have their own maps). The full block is listed for the first sensor only; for the others only primary value, status and alarm bitfield are listed - the same indices apply to every sensor block.
  • Digital input blocks are shown for the DI State type. Flow meter, counter, flow monitor and remote Modbus DI types use different maps (section 5.3.4).
  • Relay entries use the indices common to every relay control mode (time on, total time, state, reset, HOA, status, alarm bitfield). Mode-specific set points live at other indices in section 5.3.6. Pulse relay maps (section 5.3.7) differ and are not included.
  • Status register codes 37 and above are not listed in the values here; see section 5.4. Alarm bit 5 meanings vary by sensor or DI type.
  • Analog outputs and virtual inputs are left out.
  • Block start addresses are from the W900 I/O channel map (pp. 13-14): sensors in I/O slot 1 start at x1153 and slot 2 at x1729, with 36 addresses per sensor; slot 3 starts at x2305 and slot 4 at x2881 (not listed here, same layout). Digital inputs 1-12 start at x0577, relays 1-8 at x8929, control outputs 1-8 at x6913 (relay maps).
  • Analog output cards reuse the same slot address ranges as sensor cards. With the 2 AI + 4 AO card (P/N 191918) the two sensor inputs move to channels 5 and 6 of that slot.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. Questions about the Walchem W900 water treatment controller (Modbus/TCP)

What Modbus registers does the Walchem W900 water treatment controller (Modbus/TCP) have?

This map lists 138 registers: 138 holding registers. 17 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Walchem W900 water treatment controller (Modbus/TCP) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 1-based (subtract 1 for the wire address). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. Section 5.1 says the published addresses are 1-based while the packet is 0-based, so subtract 1 on the wire. Each object's address = its block start (xNNNN in the I/O channel map) + the index in its type-specific map; e.g. firmware version is block x0037 + index 2 = 30039/40039, wire address 38. The 'x' prefix stands for the table digit: the same address can be read as a holding register (FC3) or input register (FC4).

What byte order does the Walchem W900 water treatment controller (Modbus/TCP) use for 32-bit values?

Multi-register values in this map use CDAB (low word first (word-swapped)). Set your client to this order for every 32/64-bit value in the table.

What are the minimum Modbus registers to integrate the Walchem W900 water treatment controller (Modbus/TCP)?

Start with HR 36 Controller time (Controller time (proves comms)); HR 1152 Sensor 1-1 primary value (Sensor primary value); HR 1186 Sensor 1-1 status (Sensor status code); HR 1187 Sensor 1-1 alarm bitfield (Sensor alarm bitfield); HR 609 Digital input 1 state (Digital input 1 state); HR 8959 Relay 1 state (Relay 1 state); HR 8961 Relay 1 HOA setting (Relay 1 HOA setting); HR 71 System alarm bitfield (System alarm bitfield).

How do I enable Modbus control of the Walchem W900 water treatment controller (Modbus/TCP)?

Modbus/TCP is a feature of the controller; enable it and set the port and data format (normal or inverse word order) in the Remote Communications menu. A 'Verbose Logging' option there logs every message for commissioning and turns itself off at restart.
