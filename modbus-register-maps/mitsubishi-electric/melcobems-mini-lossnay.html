Short answer

Small Procon protocol converter that plugs into a Mitsubishi Electric Lossnay energy-recovery ventilator and serves Modbus RTU on RS-485 or Modbus TCP. For Lossnay units it gives on/off, ventilation mode (heat recovery / bypass / auto) and fan speed control, plus outdoor and room temperature, filter and maintenance signs, fault code, energy use and actual fan speeds.

Integration notes: Mitsubishi Electric MelcoBEMS MINI (A1M+ / A1M) gateway for Lossnay heat recovery ventilators (LGH and VL series)

Integration in brief

Set DIP 7 ON for Modbus RTU, set the node address on DIP 1-5 and DIP 6 ON for 9600 / no parity (or use Modbus TCP on port 502). Check input 9 reads 2, then switch the unit with holding 300, pick the ventilation mode at 302 and fan speed at 303, and poll the temperatures, filter sign and fault code.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

DIP switch 7 ON selects Modbus RTU on RS-485 (OFF = BACnet MS/TP and BACnet IP). The Ethernet port serves Modbus TCP on port 502.

Byte order & addressing

  • Fault code 0x8000 (decimal register: 8000) means no fault; 0x6999 / 6999 means the gateway cannot talk to the Lossnay.
  • Temperatures read 0x7FFE while the sensor is being detected and 0x7FFF when no thermistor is fitted.
  • Write fan speed 1-4 only; Auto (0) is not supported on LGH and VL units.
  • Check holding 334 / 335 before writing bypass or auto ventilation mode: they say whether the unit has a bypass damper and auto mode.

Network setup

  • RS-485 A, B and GND must all be connected; shielded cable, daisy chain only.
  • Factory IP address 192.168.92.114, Modbus TCP port 502.
  • Node address 1-30 on DIP 1-5 in binary; each converter on the bus needs its own address.

Watch out for

  • The gateway detects ATA, ATW or Lossnay by itself; the Lossnay map applies only when the system type reads 2.
  • Outdoor and room temperatures only read correctly when the matching sensor flag (338 / 339) reads 1 (equipped).

Notes on this map

  • Only rows the manual ticks for the Lossnay LGH and/or VL series are listed. Every listed row is ticked for both series.
  • Rows printed with no tick for either series are left out: operating mode (40302), temperature setpoint (40305), supply air temperature (40306 / 30175), CO2 level (40310 / 30179), thermo on/off, actual operation mode, auto fan speed availability, the 0.5 °C step / heat-cool / auto availability flags, the min/max setpoint limits, the temperature-control-unit flags and the supply-air and CO2 sensor flags.
  • All input registers, discrete inputs and the coil are mirrored as read-only holding registers (power on/off is writable on both holding 300 and coil 3).
  • Outdoor temperature comes twice: signed (two's complement, down to -56.0 °C) and an unsigned twin for BMSs that cannot handle negative values.
  • Fan speed value 0 (Auto) is marked not supported on LGH and VL units.
  • The older MelcoBEMS MINI (A1M) manual v1.1.11, section 13 (https://library.mitsubishielectric.co.uk/pdf/download_full/5186, pp. 37-49), prints the same Lossnay table, addresses and ticks; the A1M is RS-485 only (no Modbus TCP).
  • DIP switches: 1-5 node address (all OFF = 1, all ON = holding 4), 6 ON = 9600 baud no parity (OFF = holding 5/6), 7 ON = Modbus RTU (OFF = BACnet). Data bits 8 and stop bits 1 are fixed.

Are the Mitsubishi Electric MelcoBEMS MINI (A1M+ / A1M) gateway for Lossnay heat recovery ventilators (LGH and VL series) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers Modicon 3xxxx/4xxxx (drop the prefix, subtract 1). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. Every row prints a 0-based 'Addr' next to its Modicon number (40001 = holding 0, 30001 = input 0, 10001 = discrete input 0, 00001 = coil 0). The 0-based Addr is the wire address.
