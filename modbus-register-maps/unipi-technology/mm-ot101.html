Short answer

The MM-OT101 sits between an OpenTherm boiler and its thermostat (monitor mode) or replaces the thermostat (controller mode) and exposes the OpenTherm data on Modbus RTU. Each OpenTherm message ID maps straight to the register with the same number. This map covers the status flags, setpoints, temperatures, modulation, pressure, counters and remote parameters, the gateway's line settings and timing statistics, and the two mode coils.

This page lists 85 Modbus registers for the Unipi Technology MM-OT101 Modbus / OpenTherm gateway — 34 writable — with the table, 0-based wire address, data type, word order, scale, units and access of each, re-typed from Unipi Technology’s own free documentation (linked below) and checked against it.

Integration notes: Unipi Technology MM-OT101 Modbus / OpenTherm gateway

Integration in brief

In controller mode, clear coil 0, set the CH/DHW enable flags in the master status byte of register 0 and write the control setpoint to register 1 (f8.8), one register per write, repeated periodically. Read boiler status and temperatures from registers 0, 17, 25, 26 and 28.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

Set address (1-7), baud (9600/19200) and parity with the internal DIP switch: switch 1 = baud (ON 19200), switch 2 = parity (ON even), switches 3-5 = address weights 4/2/1. The gateway starts in monitor mode after power-up.

Byte order & addressing

  • Registers 0-127 must be written one register at a time; multi-register writes work only for 1000 and up (memory only).
  • f8.8 values: read as signed 16-bit and divide by 256.
  • Direct reads to the boiler can take up to about 800 ms; set the master timeout accordingly.

Network setup

  • Default: address 1, 19200 baud, even parity.
  • On some versions parity is fixed to even regardless of the switch.
  • 120-ohm termination is enabled with switch SW2.

Watch out for

  • The gateway returns to monitor mode after power-up, so the controller must re-select controller mode.
  • In controller mode the PLC must send commands to the boiler periodically.

Notes on this map

  • OpenTherm f8.8 values are signed 16-bit numbers divided by 256 (the manual's example: 1.3 is stored as 333).
  • Registers that hold two 8-bit OpenTherm fields (flag8/u8, u8/u8, s8 pairs) are listed as one UINT16; split them into high and low byte yourself. The manual does not say which byte holds which field for every pair, so check against the OpenTherm specification.
  • Left out: the 32-bit statistics counters (2004-2018 and 2104-2118), because the manual does not state their word order.
  • In monitor mode, registers 0-127 hold the last value seen passing between boiler and thermostat; messages that never passed read 0. Unmapped registers and coils also read 0.
  • The manual names separate read functions (a single-register read goes straight to the boiler in controller mode, a multi-register read returns the memory map) but gives no function-code numbers; registers are listed here as holding registers.
  • Statistics units (bit times) are not stated.
  • Register 0: the minimum-configuration table puts the master status flags (bit 0 CH enable, bit 1 DHW enable, bit 2 cooling enable, bit 3 OTC active, bit 4 CH2) in the high byte and the slave flags (bit 0 fault, 1 CH mode, 2 DHW mode, 3 flame, 4 cooling, 5 CH2 mode, 6 diagnostic) in the low byte, but the register map table prints the register as LB(flag8)/HB(flag8) for master and slave. Because the byte order is not settled, the bits are not mapped here; confirm on site.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. Questions about the Unipi Technology MM-OT101 Modbus / OpenTherm gateway

What Modbus registers does the Unipi Technology MM-OT101 Modbus / OpenTherm gateway have?

This map lists 85 registers: 2 coils, 83 holding registers. 34 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Unipi Technology MM-OT101 Modbus / OpenTherm gateway Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 0-based (the number printed is the address on the wire). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. Register numbers equal OpenTherm message IDs (0-127) and are sent unchanged; register 0 (status flags) exists, so the numbering is 0-based. Gateway registers 1000+ and coils 0/1 follow the same rule.

What are the minimum Modbus registers to integrate the Unipi Technology MM-OT101 Modbus / OpenTherm gateway?

Start with HR 0 Master / slave status flags (Status flags (CH/DHW enable, flame, fault)); HR 1 Control setpoint (CH water) (Control setpoint); HR 17 Relative modulation level (Relative modulation level); HR 25 Boiler flow water temperature (Boiler flow temperature); HR 28 Return water temperature (Return water temperature); CO 0 Monitor mode active (Monitor / controller mode).

How do I enable Modbus control of the Unipi Technology MM-OT101 Modbus / OpenTherm gateway?

Set address (1-7), baud (9600/19200) and parity with the internal DIP switch: switch 1 = baud (ON 19200), switch 2 = parity (ON even), switches 3-5 = address weights 4/2/1. The gateway starts in monitor mode after power-up.
