Short answer

Small Modbus RTU server that plugs into the S21 connector of one Daikin domestic split indoor unit. Every point is a 16-bit holding register: on/off, mode, fan, vanes, setpoint, room temperature, alarm/error code, window contact and setpoint limits. Temperatures follow the scale chosen on DIP switch SW4.

Integration notes: Intesis (HMS Networks) INMBSDAI001I000 Daikin domestic AC to Modbus RTU gateway

Integration in brief

Wire RS-485 A/B, set the slave address and baud on SW3/SW4, reboot, then poll holding registers 0-11 with function 03 and write single registers with function 06. Read register 11 for errors and keep reads to 50 registers or fewer per request.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

No enable step. Set a non-zero slave address on SW3 (address 0 = not configured) and keep register 7 (control objects disablement) at 0 so Modbus commands reach the unit.

Byte order & addressing

  • Temperatures change scale with DIP SW4 (x1 °C, x10 °C or °F); confirm before scaling.
  • Function 16 is accepted but only with a quantity of one register.
  • Maximum 50 registers per read request.
  • Line format 8-N-2 by default; the gateway auto-detects 8-N-1.

Network setup

  • Slave address on SW3 positions 1-6 (binary, 1..63; 0 = not configured, LED off).
  • Baud on SW3 positions 7-8 plus SW4 position 3; 9600 bps default.
  • 120 Ω termination on SW4 position 4.
  • DIP changes only take effect after a power cycle / reboot.

Watch out for

  • Only one indoor unit per gateway (S21 connector).
  • Writing the user setpoint does not guarantee the unit uses it: read 'AC real setpoint' (reg 23), which can differ when an external temperature is fed into reg 22 (virtual temperature function).
  • Error code 65535 means the gateway has lost the AC unit, not an AC fault.

Notes on this map

  • Every register is documented as a 16-bit unsigned holding register and no temperature range in the manual goes below zero, so temperatures are UINT16. The 'no value' marker the manual writes as -32768 is raw 0x8000 (32768) and is listed as an enum entry.
  • Temperature scale is set on DIP switch SW4: x1 °C (factory default), x10 °C or °F (no °F x10). The main register table refers to a 'SW2' that the gateway does not have; the DIP-switch section puts these options on SW4. Scale 1 / °C matches the factory default only; use 0.1 if x10 is selected.
  • Fan speed (reg 2) and U/D vane (reg 3) enums are given differently in the two tables of the same manual (main table: fan 0 Auto, 1..6 Speed 1..6, 10 Fan stop; vane 0 Auto, 1..9 Position 1..9, 10 Swing. Table 7: fan 0 Auto, 1 Low, 2 Mid 1, 3 Mid 2, 4 Mid 3, 5 High; vane 0 Off, 10 Swing). Values left empty; confirm on the unit.
  • Error code enum (around 100 Daikin codes keyed to remote-controller codes such as A0, U4) is not reproduced; see manual table 9.
  • Humidification (reg 28) and 'Block periodic sendings' (reg 97) appear only in table 7 and not in the main table; left out because the two tables disagree elsewhere.
  • Machine setpoint limit registers (1153-1156) are in °C or °F per DIP SW4; the manual does not say whether x10 applies to them.
  • Register 7 is named 'Control objects disablement' in the main table and 'Gateway disablement' in Table 7; both describe 0 = enabled / 1 = disabled for control through the gateway, so it is kept.

Are the Intesis (HMS Networks) INMBSDAI001I000 Daikin domestic AC to Modbus RTU gateway Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 0-based (the number printed is the address on the wire). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. The tables print both a 'Modbus address (base 0)' and a 'PLC address (base 1)'. The base-0 column is used as the wire address and as 'documented'; the PLC address is one higher.
