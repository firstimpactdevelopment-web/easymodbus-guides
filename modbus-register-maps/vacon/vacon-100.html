Short answer

Danfoss VACON's general purpose and flow-application variable frequency drive family, with Modbus RTU on the RS-485 terminals and Modbus TCP/UDP on the Ethernet port as standard. Fieldbus process data sits at 2001-2011 (control word, speed reference, process data in) and 2101-2111 (status word, actual speed, eight monitoring values), and every application parameter or monitor can be read directly by its ID number. This map covers the process data, key monitoring IDs, control-place parameters and the Modbus RTU/TCP settings.

Integration notes: Danfoss VACON VACON 100 family (built-in Modbus RTU / Modbus TCP)

Integration in brief

Enable Modbus RTU with ID 2208 = 1 (Modbus TCP is always on), set Remote control place ID 172 = 1, then write FB control word 2001 (1 = run) and FB speed reference 2003 (0-10000 = 0-100 % of min-max frequency) and poll 2101-2111 for status, actual speed, frequency, current and fault code. Every register number in the manual is 1-based: subtract 1 on the wire.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

Modbus RTU: set P5.8.1.1 RS-485 protocol (ID 2208) = Modbus RTU, after which its settings appear under P5.8.3 (slave address ID 2320, baud ID 2378, parity ID 2379, stop bits ID 2380, time-out ID 2321). Modbus TCP/UDP is always enabled; set the IP mode and address under P5.9.1. For control set Remote control place P3.2.1 (ID 172) = Fieldbus control, Local/remote (ID 211) = Remote, and leave Fieldbus control reference selection (ID 122) = 3 Fieldbus. Control word bits 8/9 can also force fieldbus control and reference.

Communication loss & watchdog

RTU: ID 2321 communication time-out (seconds, default 10, 0 = off). TCP/UDP: ID 2448 time-out (seconds, default 10); a connection can also set its own timeout at register 40501. The reaction is ID 733 Response to fieldbus communication fault (default 3 = fault, stop per stop function); the fault is code 53 Fieldbus communication fault.

Byte order & addressing

  • The manual's register numbers are 1-based: control word 2001 goes on the wire as 2000 (07D0h), as the manual's own write example shows; ID n is wire n-1.
  • 16-bit process data at 2001/2101 carries only the low half of the 32-bit control and status words; the full words are at 2051-2052 and 2151-2152, high word first.
  • FB speed reference and FB actual speed are 0-10000 = 0-100.00 % of the min-to-max frequency span, not Hz (manual example: 5000 = 25.00 Hz with 0-50 Hz limits).
  • Holding and input registers return the same data at the same address; coils and discrete inputs (control/status bits) work on Modbus TCP/UDP only.
  • TCP unit identifier defaults to 255 and is checked on TCP as well as UDP.

Network setup

  • RS-485 on the standard terminal block terminals A and B (A = negative, B = positive); ground the cable shield with the supplied clamp.
  • Set the RS-485 termination DIP switch (next to the keypad) to ON on the first and last device on the bus; biasing is built into the termination.
  • RTU defaults: slave address 1, 9600 baud, even parity; 300 to 230400 baud supported.
  • Ethernet: DHCP by default; switching to Fixed gives 192.168.0.10 / 255.255.0.0 / gateway 192.168.0.1. Up to three Modbus TCP/UDP connections.
  • UDP is supported from firmware FW0072V025 (INDUSTRIAL / 100 X), FW0159V016 (FLOW) and FW0065V035 (HVAC); use UDP for cyclic process data and TCP for parameter reads/writes.

Watch out for

  • Updating the control unit firmware restores defaults, which usually puts the control place back to I/O.
  • Unused control word bits must be written as 0; on 100 HVAC bits 5, 7 and 10-12 are not supported.
  • Reading 30 consecutive IDs fails with Illegal Data Address if any one ID in the range does not exist.
  • Exception 04 (slave device failure) is returned for an invalid register count, as in the manual's example.
  • Broadcast works only with function codes 06 and 16 on RTU and UDP, never on TCP.

Notes on this map

  • Register numbers are as the manual prints them (1-based); see addressing. The same values can be read as holding registers (FC03) or input registers (FC04) at the same address; only the holding-register side is listed.
  • Application IDs can be read directly: ID n is register n for IDs 1-2000 and 2200-10000 (registers 2001-2199 are process data). Up to 30 consecutive IDs per request, and the whole request fails if any ID in the range does not exist - use the ID map (10501-10530 IDs, 10601-10630 values; 10701-10760 for 32-bit) to gather scattered IDs.
  • 32-bit copies of IDs live at 20001-40000 (manual: wire address = 20000 + (ID - 1) x 2, e.g. ID 864 FB status word at 21726) and of process data at 2051-2086 / 2151-2186, high word first. Only the 32-bit status word is listed.
  • Monitoring IDs (1-1495) and parameter IDs (103-888) come from the VACON 100 INDUSTRIAL application guide; scales follow its Scale column and the Modbus manual's rule that values are sent without decimals (2500 = 25.00 Hz). VACON 100 FLOW and HVAC use their own application guides - check IDs before use.
  • Process data out 1-8 (2104-2111) are typed UINT16 because the INDUSTRIAL guide says FB DataOut values are sent in unsigned 16-bit format. Signedness is not stated for direct ID reads: frequency, speed, torque, power, temperature, PID output and analog levels read by ID are typed INT16, since their positive ranges fit below 32768 (so INT16 decodes them the same as UINT16) and unit temperature can go below 0 °C. FB actual speed (2103) is INT16 because ID 888 FB sign of actual can make it negative.
  • Process data out 1-8 (2104-2111) are the defaults of P3.6.1-P3.6.8 (IDs 852-859); if those are changed, the registers carry other values. Process data in 1-8 (2004-2011) are application-defined (e.g. torque reference when ID 64 = ProcessDataIn1) and are not listed.
  • Motor current: the Modbus manual says ID 3 / process data out 3 scale depends on drive size (always 0.1 A on 100 HVAC), while the INDUSTRIAL guide's default table shows 0.1 A. Those two registers are left unscaled; read ID 45 for a fixed 0.1 A value.
  • Left out: operation-day, energy and fault-history counters (40001-40568) and the per-connection timeout register 40501. Their tables pair holding register 40001 with input register 1, which contradicts the 1-based numbering the rest of the map uses, so the wire address is ambiguous. ID 2382 communication status (combined good/bad counter shown as 0.0-99.999) is also left out.
  • Left out: minimum/maximum frequency (IDs 101/102; the guide prints 0.00 and 320.0, so the decimals are unclear), motor nominal values with drive-dependent ranges, digital-input status IDs (bit layout not given) and motor shaft power in kW (ID 73/98, unit kW or hp).
  • ID 733 lists a range of 0-5 but only describes values 0-4.
  • ID 2380 stop bits defaults to 3 (2 stop bits) in the parameter table while the manual's parity table pairs even parity with 1 stop bit; read it back from the drive.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Questions about the Danfoss VACON VACON 100 family (built-in Modbus RTU / Modbus TCP)

What Modbus registers does the Danfoss VACON VACON 100 family (built-in Modbus RTU / Modbus TCP) have?

This map lists 78 registers: 5 coils, 8 discrete inputs, 65 holding registers. 26 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Danfoss VACON VACON 100 family (built-in Modbus RTU / Modbus TCP) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 1-based (subtract 1 for the wire address). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. The manual states that addresses in Modbus messages start at zero and prints its register map 1-based: its write example sends starting address 07D0h (2000) for control word 2001, and its read example sends 0836h (2102) for register 2103. So subtract 1 from every printed number; application ID n is register n and wire address n-1 (ID 172 -> 171). Coils 0001-0018 are 1-based too (coil 1 = wire 0), and discrete inputs printed 10001-10008 are Modicon-style references for wire 0-7.

What byte order does the Danfoss VACON VACON 100 family (built-in Modbus RTU / Modbus TCP) use for 32-bit values?

Multi-register values in this map use ABCD (high word first (big-endian)). Set your client to this order for every 32/64-bit value in the table.
