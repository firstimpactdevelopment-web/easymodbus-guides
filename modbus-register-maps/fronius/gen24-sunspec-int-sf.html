Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF Modbus register map

Updated 16 October 2026

Short answer

GEN24 hybrid inverters host Modbus TCP and RTU themselves and present a SunSpec map: common block, inverter model 101/103, nameplate, settings, status, immediate controls, multiple-MPPT (PV inputs 1-2 plus battery charge/discharge as inputs 3-4) and basic storage control. This map covers the 16-bit measurements, ratings, battery state of charge and every control register, each scaled through its SunSpec scale factor.

This page lists 162 Modbus registers for the Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF — 24 writable — with the table, 0-based wire address, data type, word order, scale, units and access of each, re-typed from Fronius’s own free documentation (linked below) and checked against it.

Integration notes: Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF

Integration in brief

In the inverter web UI (Communication > Modbus) enable the TCP server, select int+SF and tick Allow Control if you need writes; then poll unit ID 1. Read registers 40070-40109 (wire addresses 40069-40108) for live data, register 40352 (address 40351) for battery SoC, and use models 123/124 for power limits and battery windows.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

Inverter web interface > Communication > Modbus: choose TCP Server and/or RTU Server, set SunSpec Model Type (int+SF for this map), and activate 'Allow Control' for on/off, power reduction, power factor, reactive power and battery commands. 'Restrict Control' limits control to fixed IP addresses. Writes to models 123/124 raise an exception when control is not allowed.

Communication loss & watchdog

Model 123 controls have *_RvrtTms fallback timers (0-28800 s) that restart with every Modbus message; on expiry the control ends and the next-priority mode takes over. 0 (default) keeps the setting until disabled. Model 124 has InOutWRte_RvrtTms (0-28800 s) for the battery window.

Byte order & addressing

  • Off-by-one: SunSpec registers are numbered from 40001; request number minus one (40001 -> 40000).
  • Switching float/int+SF changes the address of every model after the inverter model.
  • Battery power appears as MPPT inputs 3 (charge) and 4 (discharge); only one is non-zero at a time.
  • Storage window sign convention: negative power = charging, positive = discharging; OutWRte/InWRte may be negative to force charging or discharging.
  • Writes to read-only or unsupported registers are silently ignored; out-of-range values return exception 3.

Network setup

  • TCP: inverter unit ID is always 1 (identify devices by IP address); port 502 or 1502 selectable in the web UI.
  • RTU: set Inverter address (1-247, factory 1), interface M0 or M1, baud and parity in the web UI; each inverter on the bus needs a unique address.
  • RTU wiring: 120-ohm termination enabled at both line ends, shielded twisted pair, single-point grounding, strict daisy chain.
  • Smart Meter unit ID is set via 'Meter address offset' (factory 200).

Watch out for

  • Query sequentially (at most 2 requests in parallel) with a response timeout of at least 1 s; read blocks rather than single registers.
  • Grid charging via ChaGriSet only works if 'battery charging from DNO grid' is also enabled in the system settings (the two are AND-linked).
  • Changing InWRte/OutWRte/StorCtl_Mod shows up in Solar.web as Forced Recharge or Energy saving mode.
  • After changing a value of an active mode (e.g. a new WMaxLimPct), re-write the matching _Ena register with 1.

Notes on this map

  • Register table from Fronius' official GEN24 XLSX (gen24-modbus-api-external-docs.zip, linked from the Fronius Modbus TCP open-interfaces page); behaviour and settings from the PDF.
  • Addresses assume SunSpec Model Type = int+SF and a battery configured. With float the inverter model is 111/113 and later models move by +10. Without a battery the MPPT model has only inputs 1-2 and the end block follows at 40304. Fronius advises walking the model chain from 40001 rather than hard-coding addresses.
  • Word order: neither the PDF nor the XLSX states the order of 32/64-bit values, so they are left out: SID 40001-40002, WH 40094-40095, Evt1/Evt2/EvtVnd1-2 40110-40117, ActWh 40187-40190, StActCtl 40217-40218, Tms 40223-40224, and DCWH/Tms of every MPPT input. The SID is documented as 0x53756E53 'SunS', which suggests high word first, but this is not stated.
  • DCA/DCV in the inverter model are left out: GEN24 has several DC inputs, their scale factors are marked not supported, and per-input values are in model 160.
  • Registers marked 'not supported' in the XLSX are left out (Opt, other temperatures, VMax/VMin, ramp settings, model 160 Tmp/DCSt/DCEvt, StorAval, InBatV and similar). VAChaMax (40350) is listed as writable but its scale factor VAChaMax_SF is marked not supported, so it is left out too.
  • Many scale factors are 'auto-scaled' (A, W, VA, VAr, WH, DCW, Ris, model 160): they change at runtime, so read a value and its SF in the same request.
  • Unsupported values read as: int16 0x8000, uint16/enum16/bitfield16 0xFFFF, sunssf 0x8000. Phase B/C and line-line points depend on the grid connection.
  • Settings model 121 registers are all read-only in the GEN24 map (the Datamanager map marks some writable).
  • StVnd is documented as identical to St; the PDF lists SunSpec states 1-8.
  • The Smart Meter is published at its own unit ID (default 200, then 201-204) with a separate common block and meter model starting at 40001; not part of this map.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Questions about the Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF

What Modbus registers does the Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF have?

This map lists 162 registers: 162 holding registers. 24 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 1-based (subtract 1 for the wire address). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. Fronius numbers SunSpec registers from 40001 and says to send the register number minus one: register 40001 is read at address 40000 (0x9C40). The manual's RTU example reads register 40005 (Mn) with address bytes 9C 44 (40004).

What are the minimum Modbus registers to integrate the Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF?

Start with HR 40069 Inverter ID (Inverter model ID (101/103) - confirms int+SF layout); HR 40083 W (AC power); HR 40084 W_SF (AC power scale factor (auto-scaled)); HR 40107 St (Operating state); HR 40351 ChaState (Battery state of charge); HR 40365 ChaState_SF (SoC scale factor); HR 40232 WMaxLimPct (Active power limit %); HR 40236 WMaxLim_Ena (Enable/disable the power limit); HR 40250 WMaxLimPct_SF (Power limit scale factor).

How do I enable Modbus control of the Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF?

Inverter web interface > Communication > Modbus: choose TCP Server and/or RTU Server, set SunSpec Model Type (int+SF for this map), and activate 'Allow Control' for on/off, power reduction, power factor, reactive power and battery commands. 'Restrict Control' limits control to fixed IP addresses. Writes to models 123/124 raise an exception when control is not allowed.

What happens when the Fronius Primo GEN24 / Symo GEN24 (Plus) SunSpec int+SF loses Modbus communication?

Model 123 controls have *_RvrtTms fallback timers (0-28800 s) that restart with every Modbus message; on expiry the control ends and the next-priority mode takes over. 0 (default) keeps the setting until disabled. Model 124 has InOutWRte_RvrtTms (0-28800 s) for the battery window.
