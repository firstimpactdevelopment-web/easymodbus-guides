Short answer

The Eaton H-Max is an HVAC variable frequency drive with built-in RS-485 (Modbus RTU, N2, BACnet MS/TP) and Ethernet (Modbus TCP, BACnet IP). Its Modbus map uses fixed process-data blocks for control and status plus direct access to application IDs. This map covers the control/status words, speed reference, the default process-data outputs, coils/discrete inputs and the RTU settings.

This page lists 36 Modbus registers for the Eaton H-Max HVAC drive (embedded Modbus RTU / TCP) — 16 writable — with the table, 0-based wire address, data type, word order, scale, units and access of each, re-typed from Eaton’s own free documentation (linked below) and checked against it.

Integration notes: Eaton H-Max HVAC drive (embedded Modbus RTU / TCP)

Integration in brief

Select Fieldbus as the remote control place, then write the control word to 2000 and the speed reference (0-10000 = 0-100 %) to 2002 in one write. Read status 2100 and process data out 2103-2110 for frequency, current and fault code.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

Select Modbus RTU as the RS-485 protocol (P4.7.1.1, ID 2208), set slave address, baud and parity under I/O and Hardware > RS-485, then set the remote control place to Fieldbus control (Basic Parameters > Start Src Auto) and the auto speed reference to fieldbus.

Communication loss & watchdog

P4.7.3.1.4 RTU communication time-out (default 10 s, 0 = not used) and P4.8.2.1.3 for Modbus TCP raise a fieldbus fault when polling stops.

Byte order & addressing

  • Printed addresses are 1-based: subtract 1.
  • The 32-bit control/status words are high word first; the 16-bit copies hold only bits 0-15.

Network setup

  • RTU defaults: address 1, 9600 baud, no parity with 2 stop bits.
  • Terminate both ends of the RS-485 line; the manual recommends active biasing for idle-bus stability.

Watch out for

  • The drive ignores fieldbus run commands unless Fieldbus is the active control place (status word bits 29-31).

Notes on this map

  • This copy is hosted by the US distributor Precision Electric; it is Eaton manual MN04008006E (January 2012).
  • The 32-bit status word is printed as 2151 = high data, 2152 = low data, so it is high word first (ABCD). The 16-bit control/status words at 2001/2101 carry only the lower 16 bits.
  • Process data out 1-8 scales come from the annex table (output frequency 0.01 Hz, speed 1 rpm, current 0.1 A, torque/power 0.1 %, voltage 0.1 V, DC link 1 V); the manual's read example decodes 09C4h at 2104 as 25.00 Hz. They are typed UINT16 here; signedness is not stated.
  • Registers 2002 and 2102 are reserved. Process data in 1-8 are application-defined and carry no fixed meaning.
  • All holding registers can also be read with function 04 at the same address.
  • Left out: monitoring IDs other than 37, because the H-Max monitoring table lists IDs and units but no scale; the operation-day, energy and fault-history counters at 40001-40430, which the manual prints as both 40001 and 440001, so their wire address is ambiguous; the ID map ranges (usable, but empty until configured).

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. Questions about the Eaton H-Max HVAC drive (embedded Modbus RTU / TCP)

What Modbus registers does the Eaton H-Max HVAC drive (embedded Modbus RTU / TCP) have?

This map lists 36 registers: 3 coils, 8 discrete inputs, 25 holding registers. 16 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Eaton H-Max HVAC drive (embedded Modbus RTU / TCP) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers 1-based (subtract 1 for the wire address). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. The manual says data addresses start at zero (holding register 40001 = address 0) and prints the map 1-based; its write example sends start address 07D0h (2000) for control word 2001 and its read example sends 0836h (2102) for register 2103. Subtract 1 from every printed number; application ID n is register n, wire n-1. Coils 0001-0003 are 1-based too (coil 1 = wire 0); discrete inputs printed 10001-10008 are Modicon-style references for wire 0-7.

What byte order does the Eaton H-Max HVAC drive (embedded Modbus RTU / TCP) use for 32-bit values?

Multi-register values in this map use ABCD (high word first (big-endian)). Set your client to this order for every 32/64-bit value in the table.

What are the minimum Modbus registers to integrate the Eaton H-Max HVAC drive (embedded Modbus RTU / TCP)?

Start with HR 2000 FB control word (Control word (run, direction, reset)); HR 2002 FB speed reference (Speed reference 0.01 %); HR 2100 FB status word (Status word); HR 2103 Process data out 1 (output frequency) (Output frequency 0.01 Hz); HR 2105 Process data out 3 (motor current) (Motor current 0.1 A); HR 2110 Process data out 8 (active fault code) (Active fault code).

How do I enable Modbus control of the Eaton H-Max HVAC drive (embedded Modbus RTU / TCP)?

Select Modbus RTU as the RS-485 protocol (P4.7.1.1, ID 2208), set slave address, baud and parity under I/O and Hardware > RS-485, then set the remote control place to Fieldbus control (Basic Parameters > Start Src Auto) and the auto speed reference to fieldbus.

What happens when the Eaton H-Max HVAC drive (embedded Modbus RTU / TCP) loses Modbus communication?

P4.7.3.1.4 RTU communication time-out (default 10 s, 0 = not used) and P4.8.2.1.3 for Modbus TCP raise a fieldbus fault when polling stops.
