Diehl Metering SHARKY 775 / SCYLAR INT 8 with Modbus RTU communication module Modbus register map

Updated 19 November 2026

Short answer

The SHARKY 775 ultrasonic heat meter and the SCYLAR INT 8 calculator take an extension card that polls the meter over its internal M-Bus link and serves the values as a Modbus RTU slave on RS-485. Every measurement is mirrored in both the input and holding register tables, in ten-register groups holding an integer, a unit factor, the unit as text, a unit code and an IEEE-754 float. This map lists the input-register copies of the float, unit and temperature values plus the module's own settings.

This page lists 76 Modbus registers for the Diehl Metering SHARKY 775 / SCYLAR INT 8 with Modbus RTU communication module — 7 writable — with the table, 0-based wire address, data type, word order, scale, units and access of each, re-typed from Diehl Metering’s own free documentation (linked below) and checked against it.

Integration notes: Diehl Metering SHARKY 775 / SCYLAR INT 8 with Modbus RTU communication module

Integration in brief

Wire RS-485 to terminals 90(+)/91(-), power the module with 12-24 V AC/DC on 60/61, then read input registers with function 04 at 9600 8N1. The float block of each group (energy 30009, volume 30019, power 30029, flow 30039) is ready to use; read the unit ID just before it once to know the unit.

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

Enable Modbus control & writes

No setting is needed in the meter: fit the card in extension slot 1 or 2, connect it with the ribbon cable and power it. Communication settings are holding registers 41001-41008 written with function 06 or 16.

Byte order & addressing

  • Floats and 32-bit integers are high word first (ABCD).
  • The slave ID follows the meter serial number by default (last three digits, with fall-backs for values over 247); write 41001 with high byte 0 to make it static.
  • The float values are computed by the module and can differ slightly from the meter display; the integer copies are exact.

Network setup

  • Defaults: automatic slave ID, 9600 baud, 8 data bits, no parity, 1 stop bit.
  • Hold the status button for at least 15 s to restore defaults; the LED blinks to confirm.
  • Terminate both bus ends; the module is a 1/8 unit-load transceiver.

Watch out for

  • On battery-powered meters keep the update rate above 3 minutes, otherwise the meter shows E-5 and the module reports error 0x0010.
  • Update rate 0 stops the module reading the meter, so values freeze.
  • Periodical log 0 registers (30172-30193) are only valid after writing 1 to 41008, and enabling it changes the M-Bus readout the module uses.

Notes on this map

  • The module is made by Sylop for Diehl Metering meters. Diehl's own download of this guide (diehl.com/cms/files/..._Userguide_ModbusRTU_EN.pdf) answers 401 without a login, so the link is to the unaltered copy published by the Swedish distributor Armatec.
  • Word order: the manual says the module sends the most significant register first and most significant byte first, with no byte or word swap. The worked example confirms it: energy Int32 reads 0x0000 0x3039 = 12345 and the float reads 0x4640 0xE400 = 12345.0.
  • Left out: the Int32 fixed-point copies and their UInt16 unit-factor registers (offsets 0 and 2 of each ten-register group, e.g. 30001 and 30003). The engineering value is the integer times a unit factor read at run time, so it has no fixed scale. The manual recommends these integers for exact billing values; read them together with the factor register if you need full precision.
  • Only the input-register copies are listed. Each value can also be read with function 03 at the same offset in the 4xxxx table (e.g. energy float 30009 = 40009).
  • Units of each float follow the unit ID register directly before it (8 = MJ, 9 = GJ, 3 = kWh, 4 = MWh, 20 = m3, 27 = m3/h, 34 = kW, 41 = °C, etc.).
  • Temperature integers carry one decimal (multiply by 0.1). Error code is printed as hex values and is shown here as decimal enum keys.
  • Defaults from the configuration table: slave ID 0x0101 (automatic from the last three digits of the meter serial number), update rate 15 s, 9600 baud, 8 data bits, parity 'N', 1 stop bit, log 0 disabled.

What Modbus registers does the Diehl Metering SHARKY 775 / SCYLAR INT 8 with Modbus RTU communication module have?

This map lists 76 registers: 69 input registers, 7 holding registers. 7 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the Diehl Metering SHARKY 775 / SCYLAR INT 8 with Modbus RTU communication module Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers Modicon 3xxxx/4xxxx (drop the prefix, subtract 1). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. The tables print both the Modbus register (30001/40001 style) and the Modbus address; the address is the register minus 30001 or 40001 (e.g. 40011 -> 10). The worked example reads energy with function 04 starting at address 0x0000. Input register 30001+n and holding register 40001+n hold the same measurement value.

What byte order does the Diehl Metering SHARKY 775 / SCYLAR INT 8 with Modbus RTU communication module use for 32-bit values?

Multi-register values in this map use ABCD (high word first (big-endian)). Set your client to this order for every 32/64-bit value in the table.

How do I enable Modbus control of the Diehl Metering SHARKY 775 / SCYLAR INT 8 with Modbus RTU communication module?

No setting is needed in the meter: fit the card in extension slot 1 or 2, connect it with the ribbon cable and power it. Communication settings are holding registers 41001-41008 written with function 06 or 16.
