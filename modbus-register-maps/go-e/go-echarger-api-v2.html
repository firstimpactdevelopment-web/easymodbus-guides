Integration notes: go-e go-eCharger (Modbus TCP, API v2)

Integration in brief

Enable Modbus, then connect to TCP port 502. Read CAR_STATE (100) and ERROR (107), allow charging with ALLOW (200) and set the current with AMPERE_VOLATILE (299) for dynamic load management, writing with function 16.

Minimum registers to map

Addresses are 0-based wire addresses. Enough to monitor and run the unit; map more as the job needs.

RegisterNameTypeWhyAccess
IR 100CAR_STATEUINT16Charging stateRead
IR 107ERRORUINT16Error codeRead
HR 200ALLOWUINT16Allow chargingRead/write
HR 299AMPERE_VOLATILEUINT16Set charge current (not saved)Read/write
HR 337FORCE_STATEUINT16Force charging on/offRead/write

Enable Modbus control & writes

Turn on Modbus in the app (Internet tab > Advanced Settings > Modbus) or with the HTTP API key men=true, e.g. /api/set?men=true. The port is set with msp (reboot needed).

Byte order & addressing

  • Writes must use function 16 even for one register; function 06 is not implemented.
  • Word and byte order of multi-register values follow the msr/msb settings.

Network setup

  • Enable Modbus in the app or via the HTTP API (men=true).
  • Default port 502 after enabling; change with msp and reboot.

Watch out for

  • Use AMPERE_VOLATILE (299) for frequent changes; AMPERE_EEPROM (300) is stored in EEPROM with roughly 100,000 write cycles.
  • AMPERE_VOLATILE resets to the stored EEPROM value at the next boot.

Notes on this map

  • Official go-e documentation hosted in the goecharger GitHub organisation.
  • Left out: all 32-bit and 64-bit values (voltages, currents, power, energy, power factor, ENERGY_LIMIT, RFID card energies). Their word order depends on the charger's 'modbus slave swap registers/bytes' settings (msr/msb) and no default is stated.
  • Left out: input rows printed only as a bare number (132, 144-159, 200-205, 301-322) because the table does not mark which convention they use, and ASCII/binary blocks (firmware version, MAC, serial, host name, network, RFID).
  • The source notes that byte order was swapped in firmware 60.3 and fixed in 60.4.
  • API keys psm (phase switch mode) and frc (force state) are described in the repository's API_KEYS_FIRMWARE/apikeys-en.md; only frc's values are spelled out there.
  • The v2 Modbus page does not state a unit ID; the older v1 document gives unit 1.
  • The v2 Modbus page does not list which charger models it covers.

Check it against the live device. A register map tells you what the controller can expose; the unit in front of you may differ by firmware or options. Read a few registers and compare them with the unit’s own display; for a 32-bit value the float and byte-order decoder shows all four word orders at once, so a wrong word order or scale is obvious. Questions about the go-e go-eCharger (Modbus TCP, API v2)

What Modbus registers does the go-e go-eCharger (Modbus TCP, API v2) have?

This map lists 23 registers: 3 input registers, 20 holding registers. 20 of them can be written. Registers vary with firmware, options and configuration, so confirm against the device.

Are the go-e go-eCharger (Modbus TCP, API v2) Modbus addresses 0-based or 1-based?

The manufacturer's document numbers registers Modicon 3xxxx/4xxxx (drop the prefix, subtract 1). Every address on this page is the 0-based wire address you put in the request; the documented number is shown under it where it differs. The table prints each register as Modicon number plus wire address, e.g. '40300 (299)' and '30101 (100)'. The number in brackets goes in the request PDU.

What are the minimum Modbus registers to integrate the go-e go-eCharger (Modbus TCP, API v2)?

Start with IR 100 CAR_STATE (Charging state); IR 107 ERROR (Error code); HR 200 ALLOW (Allow charging); HR 299 AMPERE_VOLATILE (Set charge current (not saved)); HR 337 FORCE_STATE (Force charging on/off).

How do I enable Modbus control of the go-e go-eCharger (Modbus TCP, API v2)?

Turn on Modbus in the app (Internet tab > Advanced Settings > Modbus) or with the HTTP API key men=true, e.g. /api/set?men=true. The port is set with msp (reboot needed).
